## 2. Черновик технического задания (ТЗ)

### 2.1. 📘 Общие сведения
* **Наименование проекта:** Автоматизированная информационная система «Колледж-Библиотека».
* **Исполнитель:** Студент группы [Твоя Группа].
* **Заказчик:** Библиотека колледжа.

### 2.2. Назначение системы
Система предназначена для автоматизации учета книжного фонда, регистрации выдачи и возврата литературы, автоматического расчета штрафов за просрочку, а также для отказа от бумажных журналов учета.

### 2.3. Функциональные возможности
1.  **Ведение каталога:** Добавление новых книг, хранение информации (ISBN, автор, название, кол-во копий).
2.  **Поиск:** Фильтрация книг по названию или автору.
3.  **Учет выдачи:** Регистрация факта выдачи книги конкретному студенту.
4.  **Учет возврата:** Фиксация возврата книги с проверкой сроков.
5.  **Биллинг:** Автоматический расчет штрафа (пени) при просрочке возврата.
6.  **Хранение данных:** Сохранение состояния системы в файлах CSV и JSON между перезапусками.

### 2.4. Интерфейсы
1.  **Графический интерфейс (GUI):** Десктопное приложение на базе **Tkinter** для работы библиотекаря (ввод данных, кнопки, таблицы).
2.  **Программный интерфейс (API):** RESTful API (JSON) для обмена данными между интерфейсом и сервером.

### 2.5. Ограничения
1.  **Локальная работа:** Система рассчитана на работу в локальной сети или на одном компьютере (localhost).
2.  **Один пользователь:** Интерфейс не поддерживает одновременную работу нескольких библиотекарей с одной базой (нет блокировок записи).
3.  **Платформа:** Требуется ОС с установленным интерпретатором Python 3.10+.

### 2.6. Проверки и тестирование
1.  Проверка формата ISBN и дат (ГГГГ-ММ-ДД).
2.  Контроль остатков (нельзя выдать книгу, если `available_copies <= 0`).
3.  Тестирование API на корректные HTTP-коды (200, 404, 409).

### 2.7. Критерии приёмки
1.  Система успешно выполняет полный цикл: "Добавить книгу -> Найти -> Выдать -> Вернуть".
2.  При перезапуске сервера данные о выданных книгах не исчезают.
3.  Штраф рассчитывается корректно (по формуле `дни * ставка`).

### 2.8. Стадии разработки
| Стадия | Описание | Срок |
| :--- | :--- | :--- |
| **Анализ** | Сбор требований, выбор стека (Python) | 1 неделя |
| **Проектирование** | Разработка архитектуры, форматов CSV/JSON | 1 неделя |
| **Разработка API** | Реализация сервера Flask и логики хранения | 2 недели |
| **Разработка GUI** | Реализация форм Tkinter и связи с API | 2 недели |
| **Отладка** | Интеграционное тестирование и фикс багов | 1 неделя |

### 2.9. Источники данных
* Справочники учебной литературы (для наполнения `books.csv`).
* Список студентов (для `users.csv`).
