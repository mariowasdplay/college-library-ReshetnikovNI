# Отчет CP1: Выбор модели ИС и средств 

## 1. Контекст и цель
Проект «Колледж-Библиотека» представляет собой информационную систему для автоматизации базовых процессов библиотечного учета в учебном заведении. Предназначена для библиотекаря система позволяет регистрировать студентов, управлять каталогом книг, отслеживать выдачу/возврат литературы. Целью разработки является создание легковесного, автономного приложения с графическим интерфейсом и локальным API, исключающего необходимость сложной настройки СУБД. 

## 2. Модель ИС
Выбрана клиент-серверная архитектура, разворачиваемая локально (localhost).
* Серверная часть (Backend): Реализует REST API для обработки запросов, бизнес-логику (включая рекомендательный алгоритм) и работу с файловым хранилищем.
* Клиентская часть (Frontend/GUI): Десктопное приложение, которое общается с сервером посредством HTTP-запросов (JSON).
* Хранение данных: Используются структурированные текстовые файлы (JSON/CSV). Это упрощает перенос системы и отладку данных, соответствуя требованиям к "Мини-ИС" без использования тяжеловесных SQL-серверов. 

## 3. Выбор средств 

| Инструмент | Роль в проекте | Обоснование выбора |
| :--- | :--- | :--- |
| Python 3.11+ | Основной язык | Современный синтаксис, строгая типизация (type hints), богатая стандартная библиотека, высокая скорость разработки. |
| Tkinter | GUI (Графический интерфейс) | Входит в стандартную библиотеку Python, не требует установки сторонних зависимостей, достаточен для реализации базовых форм и таблиц. |
| Flask | API-сервер | Легковесный микрофреймворк. Идеален для создания простого REST API с минимальным количеством кода ("boilerplate"). |
| JSON / CSV | Формат данных | JSON: стандарт де-факто для обмена данными между клиентом и сервером. CSV: удобен для пакетной загрузки/выгрузки списков книг и отчетности. |
| Git + GitHub | Контроль версий | Стандарт индустрии для командной разработки, отслеживания истории изменений (History) и код-ревью (Pull Requests). |
