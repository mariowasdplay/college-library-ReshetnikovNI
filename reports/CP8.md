# Отчет CP8: Интеграция модулей и обмен сообщениями

## 1. Схема интеграции

Система построена на вертикальной интеграции трех слоев. Поток данных при операции "Возврат книги с просрочкой":

1.  **GUI (View)**: Пользователь нажимает "Вернуть книгу".
    * *Действие:* Вызов `services.return_book(user_id, isbn)`.
    * ↓
2.  **Service Layer (Client)**: Формирует JSON-сообщение.
    * *Транспорт:* HTTP POST запрос на `http://127.0.0.1:5001/return`.
    * ↓
3.  **API Server (Controller)**: Принимает запрос, парсит JSON.
    * *Логика:* Вызывает `storage.load_issues()`, находит запись, проверяет даты.
    * *Событие:* Обнаруживает разницу дат > 0 -> Генерирует событие просрочки (расчет штрафа).
    * ↓
4.  **Storage (Model)**: Атомарная запись изменений.
    * *Эффект:* Обновление `issues.json` (установка `returned_on`) и `books.csv` (счетчик копий).
    * ↓
5.  **GUI (Notification)**: Обработка ответа.
    * *Эффект:* Получение JSON с суммой штрафа -> Отображение всплывающего окна `BOOK_OVERDUE`.

​Здесь мы проверяем не отдельные функции, а всю цепочку целиком.
​Тест 1: Успешная выдача (Happy Path)
​Действие: В GUI ввести ISBN существующей книги и ID читателя -> Нажать "Выдать".
​Ожидаемый результат:

​4. Ответы на вопросы
​1. Чем «уровни интеграции» в вашем коде отличаются и зачем так?
У нас есть два уровня:
​Уровень данных (Storage): Интеграция через файлы. Обеспечивает долгосрочное хранение.
​Уровень приложения (API): Интеграция через HTTP/JSON. Обеспечивает независимость Клиента от того, как именно Сервер хранит данные.
​Зачем: Это позволяет менять внутренности сервера (например, переехать с CSV на SQL), не переписывая ни строчки кода в Клиенте (GUI).
​2. Где у вас граница между модульными и интеграционными тестами?
​Модульные тесты: Проверяют функции calculate_fine или generate_id в изоляции (без запуска сервера, просто вызов Python-функции).
​Интеграционные тесты: Требуют одновременного запуска api.py и app.py. Они проверяют, что нажатие кнопки в окне приводит к изменению файла на диске. Граница проходит по сетевому вызову: если тест делает реальный HTTP-запрос — это интеграция.
