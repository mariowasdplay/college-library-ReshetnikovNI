# Отчет CP2: Архитектура и шаблон проекта

## 1. Архитектурные решения (слои/модули)

Для реализации выбран **Клиент-Серверный подход** с четким разделением на модули:
* **Presentation Layer (GUI):** Ответственность за отрисовку и ввод.
* **Service Layer (API):** Центральная точка принятия решений и бизнес-логика.
* **Data Access Layer (Storage):** Модуль для работы с файлами (JSON/CSV), изолирующий остальную систему от деталей хранения.

## 2. Потоки данных: кто с кем и что передаёт

Обмен данными происходит в формате **JSON** по HTTP-протоколу.
* **Чтение**: GUI запрашивает данные (`GET /books`) -> API загружает книги из `books.csv` -> преобразует в JSON-массив объектов и отправляет клиенту.
* **Выдача**: Клиент отправляет JSON-объект `{"user_id": "...", "isbn": "..."}` на `POST /issue`. Сервер проверяет наличие копий и обновляет два файла (`books.csv` и `issues.json`).

## 3. Почему такая декомпозиция проще для отладки

* **Изоляция ошибок**: Проблемы в GUI (например, ошибка прорисовки окна) не влияют на бизнес-логику сервера.
* **Независимое тестирование**: Можно тестировать сервер (проверять API-методы) без необходимости запускать GUI. Если API возвращает корректный JSON, сервер работает правильно.

## 4. Ответы на вопросы

**1. Если объединить сервер и GUI в один процесс — что вы выиграете/проиграете именно у вас?**
* **Проигрыш:** В однопоточном Tkinter-приложении **GUI будет "замораживаться"** (станет неотзывчивым) при выполнении длительных операций, таких как чтение или запись больших CSV-файлов, так как эти операции блокируют основной поток.
* **Выигрыш:** Ускорится работа, так как не будет сетевых задержек.

**2. Как вы формально отделяете «модель данных» от «сервисной логики»?**
* **Модель данных (`src/common/models.py`)**: Это пассивные **классы-контейнеры** (например, `Book`), которые только *хранят* информацию (ISBN, название). В них нет методов для принятия решений.
* **Сервисная логика (`src/server/api.py`)**: Содержит **функции** (маршруты Flask), которые *принимают решения*, основываясь на бизнес-правилах (например, "проверить, что `available_copies > 0` перед выдачей").
