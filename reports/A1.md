# A1 — Предпроектное обследование и жизненный цикл

## 1. Жизненный цикл системы
Для разработки мини-ИС «Колледж-Библиотека» выбран итеративный жизненный цикл.

1. **Инициирование**
   - *Вход:* Идея автоматизации библиотеки.
   - *Выход:* Устав проекта, репозиторий на GitHub.
   - *Методы:* Мозговой штурм, настройка окружения (Termux/PC).
   - *Риски:* Технические проблемы с инструментарием.

2. **Сбор и анализ требований (КП 1, А1)**
   - *Вход:* Описание задачи от преподавателя.
   - *Выход:* Отчеты CP1.md, CPA1.md.
   - *Методы:* Анализ предметной области, декомпозиция задач.
   - *Риски:* Неполное понимание бизнес-логики выдачи книг.

3. **Проектирование данных и API (КП 2)**
   - *Вход:* Требования к сущностям (Книги, Студенты).
   - *Выход:* JSON-схемы, спецификация маршрутов Flask.
   - *Методы:* Проектирование схем данных, REST-дизайн.
   - *Риски:* Неверная структура JSON, требующая переделки в будущем.

4. **Проектирование UI (КП 3)**
   - *Вход:* Функциональные требования.
   - *Выход:* Макеты экранных форм Tkinter.
   - *Методы:* Эскизирование (Wireframing).
   - *Риски:* Сложность реализации современного дизайна на Tkinter.

5. **Разработка Бэкенда (Сервер)**
   - *Вход:* Спецификация API.
   - *Выход:* Работающий `server.py`.
   - *Методы:* Программирование на Python (Flask), работа с файлами.
   - *Риски:* Проблемы с кодировками при чтении файлов.

6. **Разработка Клиента (GUI)**
   - *Вход:* Макеты UI, работающий API.
   - *Выход:* Приложение на Tkinter с сетевыми запросами.
   - *Методы:* Верстка форм, привязка событий.
   - *Риски:* "Зависание" интерфейса при ожидании ответа сервера.

7. **Интеграция модулей**
   - *Вход:* Клиент и Сервер.
   - *Выход:* Связанная система.
   - *Методы:* Отладка взаимодействия через HTTP (requests).
   - *Риски:* Ошибки парсинга JSON на клиенте.

8. **Реализация бизнес-логики (Поиск/Выдача)**
   - *Вход:* Базовый CRUD.
   - *Выход:* Реализованные функции выдачи и возврата.
   - *Методы:* Алгоритмизация проверок (доступность книг).
   - *Риски:* Логические ошибки (выдача книги, которой нет).

9. **Тестирование**
   - *Вход:* Готовая система.
   - *Выход:* Список багов и отчет об исправлении.
   - *Методы:* Ручное тестирование сценариев использования.
   - *Риски:* Пропуск критических сценариев.

10. **Внедрение и документирование**
    - *Вход:* Стабильная версия.
    - *Выход:* Итоговый отчет, инструкция пользователя.
    - *Методы:* Написание документации (Markdown).
    - *Риски:* Нехватка времени на качественное оформление.

## 2. Анализ предметной области

**Цель системы:** Автоматизация учета библиотечного фонда колледжа для отказа от бумажных формуляров, ускорения процесса выдачи книг и получения статистики по должникам.

**Заинтересованные стороны:**
- **Библиотекарь (Основной пользователь):** Работает с GUI, выдает книги.
- **Разработчик (Я):** Поддерживает код, управляет файлами данных.
- **Студенты:** Косвенные участники (их данные хранятся в системе).

**Объекты:**
- **Книга:** (ID, название, автор, год, всего штук, доступно).
- **Студент:** (ID, ФИО, группа).
- **Выдача (Issue):** (Связь Книга-Студент, дата выдачи, дата возврата).

**События:**
- Добавление новой книги в каталог.
- Регистрация нового студента.
- Выдача книги (уменьшение счетчика доступных).
- Возврат книги (увеличение счетчика доступных).
- Поиск должников.

**Ограничения:**
- Стек: Python 3.11+, Tkinter, Flask.
- Хранение данных: Локальные файлы JSON (без SQL).
- Интерфейс: Десктопное окно (не веб-браузер).
- Ресурсы: Один разработчик.

## 3. Постановка задач обработки данных

1.  **Входные данные:**
    - Данные форм (название книги, ФИО студента).
    - Поисковые запросы библиотекаря.
    - Команды управления (кнопки "Выдать", "Принять").

2.  **Обработка (Operations):**
    - **Валидация:** Проверка, что поля не пустые и `available_count > 0` перед выдачей.
    - **CRUD:** Создание, чтение, обновление записей в списках Python.
    - **Сериализация:** Преобразование объектов Python в JSON-строки.
    - **Сохранение:** Запись JSON-строк в файлы `data/*.json`.
    - **Фильтрация:** Поиск книг по вхождению подстроки в название.

3.  **Выходные данные:**
    - Обновленные таблицы на экране (список книг).
    - Статусные сообщения ("Книга выдана успешно", "Ошибка: книги нет в наличии").
    - Файлы `books.json`, `issues.json` с актуальным состоянием.

## 4. План управления проектом (микроуровень)

Т.к. проект разрабатывается индивидуально, все роли выполняет один человек.

| Веха (Milestone) | Дата (Ориентир) | Ответственный (Роль) | Критерий готовности |
| :--- | :--- | :--- | :--- |
| **Анализ и Архитектура (КП1-2)** | Неделя 1 | Аналитик | Готовы отчеты CP1, CPA1, CP2 и JSON-файлы. |
| **Прототип UI (КП3)** | Неделя 2 | UI-дизайнер | Окно Tkinter запускается и показывает заглушки. |
| **Базовый Backend (КП4-5)** | Неделя 3 | Backend-разработчик | Сервер Flask отвечает на GET/POST запросы. |
| **Интеграция (КП6-7)** | Неделя 4 | Fullstack-разработчик | Кнопки в GUI реально меняют данные на сервере. |
| **Логика и Тесты (КП8-9)** | Неделя 5 | Тестировщик | Пройден цикл "Выдача -> Возврат" без ошибок. |
| **Финал (КП10)** | Неделя 6 | Менеджер проекта | Репозиторий сдан, документация полная. |

**Риски:**
1.  **Сложность Tkinter:** Библиотека устаревшая, сложно делать красивые таблицы. *Решение:* Использовать `ttk.Treeview` и простые стандартные виджеты.
2.  **Рассинхронизация:** Ошибки при одновременном чтении/записи файлов. *Решение:* Поскольку сервер однопоточный (Flask dev server), риск минимален для учебного проекта.

## 5. Проверочные вопросы

**1. Какой этап жизненного цикла будет “бутылочным горлышком” именно в вашей ИС и почему?**
"Бутылочным горлышком" станет этап **Интеграции модулей (GUI + API)**. Это связано с тем, что Tkinter работает в основном потоке, и сетевые запросы к серверу (Flask) могут "замораживать" интерфейс. Потребуется аккуратная реализация вызовов, чтобы приложение оставалось отзывчивым.

**2. Какая одна метрика покажет, что «анализ» провалился, даже если разработка идёт?**
Метрика — **количество изменений в структуре JSON-файлов** после этапа разработки кода. Если в середине проекта придется добавлять новые обязательные поля в `books.json` или менять типы данных, это будет означать, что этап анализа предметной области был проведен поверхностно.
